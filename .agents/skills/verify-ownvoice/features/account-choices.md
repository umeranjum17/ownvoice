# Account choices (How Ownvoice writes)

Home's **How Ownvoice writes** screen (`/source`) lists the writer options as cards: **On this phone**, **With your ChatGPT**, **With your Claude**, and **With your OpenRouter**. The chosen card shows how that account is doing; the phone and a signed-in account can be switched between, switching to a cloud account asks first (or signs in inside its card), and the writer and the reply rating both send through the chosen account.

## Sub-features

- `writer-list`: the screen lists this phone, ChatGPT, Claude and OpenRouter, in that order. OpenRouter's card reads **With your OpenRouter** / **Your own key, paid as you use it** (it is billed per use, not a plan).
- `writer-chatgpt`: the ChatGPT card signs in with the device code (copy and open, then Continue) and signing out falls back to the phone where it can write.
- `writer-claude`: the Claude card opens the Claude page and pastes the code it shows back into the field; a signed-in Claude account produces drafts through the writer.
- `writer-claude-live`: with a real signed-in Claude account, a bubble tap over a reply field produces a Claude draft and inserts it, and the Shorter selection rewrite returns through Claude; each leg is backed by the on-screen text and by the real Claude answer on logcat (drive with `mobile/e2e/claude-draft-proof.mjs`).
- `writer-openrouter`: the OpenRouter card is a key route, not a plan sign-in — the person pastes their own OpenRouter key into the field and the kit saves it only in this phone's secure store (no page to open, no code to poll). The default writer is DeepSeek V4.1 Flash; a signed-in OpenRouter account produces real drafts through the kit (`Accounts.respondKey`), never a direct provider SDK or hand-rolled HTTP.
- `writer-openrouter-unavailable`: when the kit reports the key route not ready (`route('openrouter:key').readiness !== 'ready'`), Ownvoice offers no OpenRouter card in How Ownvoice writes and no OpenRouter action on Home, even when the stored choice is OpenRouter (`src/chatgpt/accounts.ts` `openRouterReady`, `app/source.tsx` `openRouterOffered`, `app/index.tsx` `signIn` guard). The app decides nothing itself; it reflects the kit's readiness. Proved with an injected capability counterfactual (below) — app-response evidence, not live-vendor evidence.
- `writer-fixture-separation`: with a cloud key writer chosen, the demo ChatGPT stand-in's fixed drafts are never its result. Proved live and credit-free by `mobile/e2e/openrouter-proof.mjs` with `OPENROUTER_SCENARIOS=negative`: the empty OpenRouter account produced no draft and the panel refused with its own line, while the same build's ChatGPT stand-in control produced exactly its fixed text (an exact-string leak check, not a fuzzy string difference). What stays NOT PROVEN is the positive side — that a *successful* cloud generation (needs a funded account) is the panel's result and differs from the stand-in; Main2505 (top-up answered NO) closed that as needs-credit. An earlier run's dispatch marker was invalid (it fired before the awaited response); do not revive it.
- `writer-routing`: with Claude chosen, replies, polish and the reply rating all reach Claude; with ChatGPT they reach ChatGPT; with OpenRouter they reach OpenRouter; the chosen account's own plain lines show on failure.
- `writer-plain-words`: no screen shows technical words.

## How to get to it (user POV)

- Home › **How Ownvoice writes**, or the writer button on Home's readiness card (`/source?start=<the chosen account>` when it is signed out).
- Pick a card; switching back to **On this phone** is immediate, switching to an account asks once, then **Switch to Claude**, **Switch to ChatGPT** or **Switch to OpenRouter**.

## Driving it with a release build and the DPAD/tap recipe

Preconditions:

- Explicit emulator allocation; a release APK (a live writer needs a signed-in plan; the on-phone model cannot run on an emulator). For emulator-only acceptance a signed ChatGPT stand-in is enough for the ChatGPT leg.
- `ANDROID_SERIAL=emulator-NNNN`; `adb`, `zip`, `tesseract`, `magick` on `PATH`; use `.agents/skills/verify-ownvoice/evidence.sh` for the before/after and motion capture.

- **List and sign-in.** `am start -n dev.ownvoice.next/.MainActivity`, then open the writer row and capture the four cards. For the ChatGPT leg use the `EXPO_PUBLIC_E2E_GPT=1 EXPO_PUBLIC_E2E_STUB=1` build (in-step code stand-in). For the Claude leg, finish the kit's own paste flow on the person's session, then tap the bubble in a chat field and read the inserted draft back. For the OpenRouter leg, run `mobile/e2e/openrouter-proof.mjs` (same build): it finishes setup with no writer (hardware Back), opens the writer list (`/source`), taps the **With your OpenRouter** card, pastes the key from `OPENROUTER_KEY_FILE` (`~/.config/openrouter/api_key`) into the kit's own field via `adb shell input text` (never printed, logged, committed or screenshotted), connects, then types a real reply into a Chrome text field and taps the bubble for a real DeepSeek polish panel (with a Shorter rewrite), light and dark. It refuses to run if the writer list does not offer OpenRouter, which means the kit reported its key route not ready. Set `OPENROUTER_SCENARIOS=negative` for the credit-free refusal journey: it selects OpenRouter (key connected, possibly an empty account), taps the bubble, and asserts the panel's text never contains the ChatGPT stand-in's fixed drafts while the same build's ChatGPT stand-in control produces them; it then runs the unavailable-route leg. It never needs a funded account (a paid generation is only for the default full journey's real-draft comparison). Pass an optional third argument, an APK built with `EXPO_PUBLIC_E2E_OPENROUTER_OFF=1`, to add the `writer-openrouter-unavailable` journey: the writer list shows no OpenRouter card and Home (with OpenRouter seeded as the stored choice) shows no OpenRouter action, in light and dark, at phone width and font 1.3. That build is a deliberate injected capability counterfactual on a no-phone emulator, never a distributable build, so it proves the app's response to an unavailable route, not a live vendor outage.
- **Live Claude draft and rewrite.** `ANDROID_SERIAL=emulator-NNNN OWNVOICE_AVD_NAME=<its-avd> node e2e/claude-draft-proof.mjs <release-apk> [out]` needs a release APK built with `EXPO_PUBLIC_E2E_CLAUDE_LOG=1` (dev-only: `askCloud` then logs `Ownvoice claude answer: …` to logcat so a proof can read the real answer; never set in a distributable build) and an app already signed in to and switched to Claude. It installs the APK and the X-style `com.twitter.android` Composer fixture, confirms Claude on the writer list (switching to it when signed in), then drives the reply field (bubble → Claude drafts → **Insert**) and the `RewriteActivity` Shorter leg, writing the screenshots plus `claude-real-reply-*` and `claude-real-rewrite-*` trees and `claude-real-*-answer.{txt,logcat}` with the real Claude answer.
- **Routing.** With each account chosen, tap the bubble over a reply field and confirm a draft lands; the providers must show their own failure lines (Claude's say Claude, ChatGPT's say ChatGPT, OpenRouter's say OpenRouter).
- **Proof.** Copy the writer-choice and draft screenshots into `verify-artifacts/<task>/account-choices/` with the driver/CLI transcript (stable per-task folder — see the skill's Review evidence).

## Gotchas

- Emulators have no phone writer: the ChatGPT stand-in and the allocated Claude credential lead, and the OpenRouter leg reaches the real API; never claim phone-writer behavior from an emulator run.
- The OpenRouter key is a real, billable secret: read it only into the app's paste field, and never print, screenshot, commit or log it; the emulator proof build reaches the real OpenRouter API (no stand-in).
- The `/source` screen is where accounts are switched and added after setup; the first-run writer step (`/setup`) now offers Claude too, with the same paste-back sign-in (`src/ui/ClaudeSignIn.tsx`). OpenRouter is added only from `/source`, not in first-run setup, so the proof reaches it there.
- `pair` force-stops the app and loses the accessibility binding, and a cleared-data setup loses the account: re-run the sign-in and the off/on service toggle inside the launch command.
- Never read or copy another tool's Claude/ChatGPT credentials; the Claude leg uses only the allocated test credential.
- The Claude sign-in is its own browser page and cannot be scripted: the account must be signed in on the emulator beforehand. `claude-draft-proof.mjs` fails plainly when the writer list shows Claude's sign-in flow, rather than proving anything with a stub.
- The unavailable-route leg is an injected capability counterfactual (`EXPO_PUBLIC_E2E_OPENROUTER_OFF=1` forces the kit's not-ready branch), never a real vendor outage; report it as the app's response to an unavailable route, never as live vendor evidence. A stored writer choice whose route is no longer ready still shows its "What happens to your writing" privacy note on `/source` (the card and Home action are correctly absent); that is a known cosmetic limit, not a reachable card or action.
- `writer-fixture-separation`: the negative (the stand-in's fixed drafts are never the chosen cloud writer's result) is proven by the `OPENROUTER_SCENARIOS=negative` journey — an exact-string leak check plus the same build's ChatGPT stand-in control. The positive (a funded account returns a real result that differs from the stand-in) stays needs-credit per Main2505. An old dispatch marker fired before the awaited response and is never evidence of success; do not revive it.
- An empty OpenRouter account does not make the key route unavailable: `openRouterReady()` is a static capability (`route('openrouter:key',{platform:'rn'}).readiness`), so `/source` and Home still offer the card; only the generation fails, which the panel shows as its own refusal line. The card-absent/Home-action-absent refusal appears only under the injected `EXPO_PUBLIC_E2E_OPENROUTER_OFF` counterfactual. Do not conflate an empty account with an unavailable route.
