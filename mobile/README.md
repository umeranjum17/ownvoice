# Ownvoice mobile app

The Expo app contains the TypeScript core and an Android-only accessibility bridge in `modules/ownvoice-native`. First-run setup includes: a welcome that starts the one-time model download quietly, the permission explained kindly (with the animated switch hint, Not now, and the greyed-switch help), a practice chat whose first inserted draft ends the step (the bubble works on this screen only through a practice allowance that is never saved and never overrides pause), and "Where should I help?" offering the installed apps among X, LinkedIn, Reddit, Slack, WhatsApp and Gmail, with the offered bubble choices on by default, followed by an optional ChatGPT sign-in. Setup opens by itself on a fresh install and comes back to the front after the service connects (`ownvoice://setup` deep link); hardware Back finishes setup, while **Not now** skips the permission or optional ChatGPT offer and signing in finishes after app choices are saved; the step plus inserted state survive process death in the kv-store (`src/core/store.ts`, expo-sqlite). The app also has a bubble that reads the focused field and visible screen text on tap, a transparent React Native drafts panel with ChatGPT drafts when chosen or phone drafts through ML Kit GenAI, and Home and settings screens for power, pause, app choices, Your voice and read history. See [ChatGPT integration](#chatgpt-integration) for sign-in, per-app drafting choices and the phone fallback. This app is not yet a replacement for the full experience described in the [main README](../README.md).

The fictional chat with Sam and its empty **Message** field are in setup's **Try it** step. Home shows whether Ownvoice is off, getting ready (with progress), not ready (with **Try again** only while on), paused or ready. Its power switch opens setup to turn the service on in Android settings, or stops the service when turned off. **Where the bubble shows** lists launcher apps with icons, switched-on apps first, a search field and a privacy note; Ownvoice itself starts off outside the practice step. **Your voice** lets you edit never-say phrases, the writing note and two writing rules, or pick a file and preview its phrases and rules before **Add these** or **Cancel**. **What Ownvoice read** lists each bubble tap's app, time and help given, without message text; entries older than 30 days are pruned when accessed in the app or when the service next starts or handles an event after a day. **Wipe everything** removes the log, the last captured screen and Your voice. Home also has **Pause for now** and a guidance row for rewriting selected text. Selecting text in another app and choosing Ownvoice, or sharing plain text to it, opens the React Native rewrite sheet without accessibility permission. An empty selection asks you to select text first; otherwise **You selected** shows your text and promises a preview before anything changes. Choose **Shorter**, **Simpler** or **Fix spelling**; editable selections offer **Replace** (which also copies the rewrite in case the app ignores it) and **Copy**, while read-only selections and shares offer only **Copy**. The bubble hides while this sheet is open. Enable the app you want under **Where the bubble shows** to see its bubble. The coral Dot bubble appears only in enabled apps while not paused or showing the panel. It starts at the right edge halfway down; drag it out of the way and it snaps to the nearer edge, remembering a separate spot for each app. When the keyboard opens over a focused field, the bubble moves up if needed to stay above it, then returns to its saved spot. Tap it to get replies when the field is empty, improved versions of text already typed ("Polish your message"), or versions of a new post ("Polish your post"); then choose **Insert**/**Use this** or **Copy**. Replies aim for three slots (agree; kindly disagree; ask the one thing needed); unusable or repeated replies can leave fewer cards. Duplicate drafts are dropped after normalizing case, punctuation, emoji, whitespace and one leading agreement word; polish rejects versions that flatten paragraph breaks or change list markers. Long dashes are removed unless the writer's text uses one and their no-dashes rule is off. When every shown reply card has the same verdict, its repeated note is hidden; differing verdicts stay beside their cards. **Why?** on any card shows an instant rules row, then the phone model's checks where available, cached per draft. If the other checks cannot run, the cover says its earlier lines came from reading your writing. **Write new ones** reruns with the shown texts excluded; a run with no usable drafts offers **Try again**. If the phone needs to prepare its writing model, the panel shows **Getting Ownvoice ready…** with a progress bar when available before switching to **Writing…**; unsupported phones and other failures show a plain-language message only. Insertion checks the field afterward and copies the draft if it fails. The Home screen and drafts panel use the phone's colours, font and light/dark setting; Dot also appears in the panel and launcher icon. The panel closes with the top-right X, Back or a tap outside.

## Android build and device checks

Run `npx expo prebuild --platform android --no-install`, then build a release APK from `android/` with `./gradlew assembleRelease --no-daemon`. For emulator acceptance only, build with `EXPO_PUBLIC_E2E_STUB=1`; never use that flag for a distributable build. The local module is discovered from `modules/` by Expo autolinking. Release builds avoid the emulator's shared Metro port. `node e2e/driver.mjs <release-apk> [screenshots-dir]` requires `ANDROID_SERIAL=emulator-NNNN`, `adb`, `tesseract` and ImageMagick's `magick` on PATH, and refuses phone serials. It installs the release APK, checks read-back for the React Native field and Chrome textarea/contenteditable, exercises paused/off bubble prevention and service rebind after reinstall, then saves screenshots in the requested directory (by default `e2e/artifacts`). The driver uses screenshot OCR to target controls, adb shell input and window dumps, never UiAutomator (which unbinds accessibility services). Emulators have no phone model, so the flagged build writes three fixed drafts without changing device settings. `node e2e/first-run.mjs <release-apk> [screenshots-dir]` uses the same emulator-only tools and `ANDROID_SERIAL`, walks setup twice (light and dark), and saves `light-NN-*`/`dark-NN-*` screenshots; see [`reports/OWNVOICE-RN-06.md`](reports/OWNVOICE-RN-06.md). `ANDROID_SERIAL=emulator-NNNN node e2e/settings.mjs [screenshots-dir]` exercises Home, app choices, file import and read history on the installed emulator; see [`reports/OWNVOICE-RN-07.md`](reports/OWNVOICE-RN-07.md). `ANDROID_SERIAL=emulator-NNNN OWNVOICE_AVD_NAME=<owned-avd-name> node e2e/rn08.mjs <release-apk> [screenshots-dir]` verifies the target emulator's AVD name before any install or device changes, then launches the rewrite sheet directly with Android process-text and share intents (not the selection-menu chooser), checks the Replace fingerprint, read-only Copy, new-number warning and hidden bubble, and can capture the drafts panel's verdict note in light and dark.

Use a throwaway `HOME`, npm cache, Gradle home and AVD home inside the worktree for local validation. The automated driver is emulator-only; phone installs require explicit permission and must not replace the existing app. Do not modify installed-tool configuration.

## ChatGPT integration

**ChatGPT** on Home opens an optional sign-in: tap the button, approve the displayed code on the page that opens, then choose which bubble-enabled apps may use ChatGPT. Slack's ChatGPT choice starts off, though its bubble starts on when offered in setup. While a sign-in code is displayed, **Cancel** stops the attempt and returns to the previous screen. Sign-in uses byokit's device-code flow and Expo SecureStore for credentials; sign-out requests revocation and clears the app choices, and starting a new sign-in clears them too. When signed in and ChatGPT has been saved as on for an app, the drafts panel uses streamed ChatGPT Responses as its main writer. Otherwise it writes on the phone; if a request starts but fails, it falls back with a plain failure reason. If sending is stopped before a request starts, it says only that this phone wrote the drafts (or that ChatGPT is turned off). Both writers share the same draft acceptance rules.

**Privacy:** For an enabled app, ChatGPT drafting sends the text being rewritten or replied to, visible screen context and writing rules to OpenAI. Phone-only drafting does not send that content. The read log stores one native tap fact per bubble tap (app, time, what was read and whether a ChatGPT request started), not the screen or message text, for up to 30 days. Checking the public remote switch makes a GET to GitHub without app-added identifiers; the request still exposes ordinary connection information such as the device's IP address to the host. The signed switch accepts newer verified choices, retains the last verified choice if fetching fails, and is checked again before sending; before any verified flag, it defaults to on. If saving a verified choice fails, that choice lasts only until the process restarts; after a restart with no network, an older saved choice may apply. No switch file has been published. A switch permitting ChatGPT never overrides per-app consent. Immediately before starting a ChatGPT request, the app checks its latest sign-in, pause, app choice and switch state; withdrawing consent before this last check keeps drafts on the phone.

For an opt-in, outside-CI Responses proof using a throwaway copy of an existing sign-in, see [`scripts/live-proof.ts`](scripts/live-proof.ts) and its [recorded result](reports/live-proof.md). Do not pass the installed sign-in file directly or commit credentials.

To produce a switch flag offline, keep a 32-byte private signing key as hex outside this repository and, from `mobile/`, run `SWITCH_SEQ=1 node --experimental-strip-types scripts/sign-switch.ts /path/to/private-key off` (increment the sequence for later flags). This prints the signed JSON; it does not publish it. Never commit the private key.
