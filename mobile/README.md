# Ownvoice mobile app

## Known limit in 1.0.3: no generic reply cards

The drafts panel withholds empty-field replies before selecting or invoking any writer. `Panel.start` clears prior cards and invalidates the previous run first, then shows the non-retryable unavailable message. This covers initial, streamed, final and retry cards, injected writers, and phone fallback; the original Kotlin `DraftActivity` stops before drafting too. No new checker or style-note grounding is added. Typed polish and selection rewrite remain separate and retain their existing consent/cancellation boundaries. P09 name preservation is still required and open; this cut does not qualify typed-polish output. Full selected validation and actual current-candidate native acceptance remain release requirements.

Setup's practice step now asks for a typed reply to polish, or Skip. Reply screenshots, streaming timings and reply-generator descriptions below are historical/dormant behavior, not available panel behavior in 1.0.3. The writer helpers and shared engine still exist, but the panel does not invoke them for an empty field. This source checkpoint is **not verified on the real app**: no matching candidate build/device lifetime was allocated to this worker.

**Check my spelling as I type** (Home, off by default, stored as `typingCheck` in the native prefs) is the one time Ownvoice reads without a tap. `OwnvoiceService` listens to `TYPE_VIEW_TEXT_CHANGED` only while it is on, from switched-on apps while not paused; a change only re-arms a 700 ms pause, and nothing is read per keystroke. At the pause it reads the focused, editable, non-password field once, and text of at least 12 characters and three words that differs from the last checked text goes to JavaScript as `onTyped({ app, text })`; if no screen of Ownvoice is open, the service starts the React Native host headless and the pause waits until `src/core/typingCheck.ts` listens. One check runs at a time; a newer pause replaces any waiting one. The check (`src/core/typing.ts`) counts unknown words from Hunspell's English dictionary (`nspell` with dictionary-en 4.0.0's files, kept in `assets/dictionary/` with their license and read on first use, `src/core/speller.ts`), a short hand-written list of slips (its/it's, lets/let's, a/an, doubled words, lowercase i, a missing capital, then/than; lowercase i and a missing capital only when the text uses capitals elsewhere) and the `slop.ts` marks with Your voice's rules. There is no advisory your/you're rule: a short next-word list cannot reliably distinguish possessive noun phrases such as "your right hand" and "your welcome letter". Spelling still offers the missing apostrophe in "youre". The count shows as an amber badge on Dot (`showSlips`, dropped when another app comes to the front or the field falls below the minimum); suggestions are never worked out on a pause. A tap opens the usual panel, which lists each slip under **Check these** with its own **Fix**; Fix inserts the typed text with that one slip fixed through the same insert path as a draft, only when pressed. Nothing is sent, the text is held only until the pause, and no read-log entry is written per pause. The service logs `typing check ms=… badge ms=…` for each answer, which is how the on-phone timing is measured.

## Own posts from a blank composer

`Panel.modeOf` reads a blank focused field in a feed app as the `own` mode rather
than the empty state; chat and mail composers keep the empty state, and an empty
box with no field keeps **Nothing to help with**. `own` sets `DraftRequest.own`,
runs the writer through the same reply path (slots, streaming, per-slot retry,
`acceptReplies`, avoid list) with `ownPrompt`/`phoneOwnPrompt` instead of the reply
prompt, and never sends the screen behind the composer: it carries no topic. Both
writers then pass every opening through `cleanOwn` (`../packages/engine/src/drafts.ts`),
which keeps only a question with no invented number, time or `we` that fits the
place's cap, so an inventing writer leaves the panel empty with **Try again**
rather than a made-up post. The cards, ratings, tone line, **Why?**, **Edit** and
**Use this** are the shared ones, `post` is true so post checks apply, and there is
no **Yours** card because nothing was typed. `mobile/e2e/own-post.mjs` proves it
against the blank X-style composer fixture in `mobile/e2e/fixture/`.

## Cleaned up acceptance

The user-facing behavior is described in [Polish what you wrote](../README.md#polish-what-you-wrote). Both phone and ChatGPT polish use `src/core/polish.ts` for initial acceptance and retry. Before creating any version, each real writer checks that the original expresses an understandable point; only an explicit `CLEAR` answer proceeds. An explicit `UNCLEAR` answer returns no versions, never an unchanged-text notice or a fallback to the other writer; the panel says the text has no clear message to polish yet, retains **Check these**, and keeps Dot in the normal header. A malformed answer is a transient failure, not evidence of an unclear point, and follows the existing fallback/retry path. This adds one model call per polish tap through the existing writer and consent path; it is not a guarantee that every semantic judgement is correct. It seeds slot 0 with `fixedSlips` from `src/core/typing.ts` applied only to the original text, ignoring writer answers and retries for that slot. Both writers request only Shorter and Main point first. Automatic contraction fixes reuse the lowercase keys of the null-prototype `APOSTROPHE` map, excluding `AMBIGUOUS_APOSTROPHE`; inherited object keys cannot match. Other automatic spelling covers only unknown lowercase words in the three-entry `AUTO_SPELLING` map; dictionary suggestions remain advisory. The app dictionary adds the missing common term `autosave`, so the advisory list does not suggest the unrelated dictionary word `autoclave`. Spelling corrections run before doubled-word removal, which uses `DOUBLE_WORDS` (articles only), a lowercase first occurrence, and whole-word boundaries outside handles, tags, URLs and emails. Other repeated words stay unchanged in Cleaned up. After spelling and repetition cleanup, the only automatic grammar rule is `Its`/`its` immediately before a space and the lowercase whole word `a`, `an` or `the`, preserving case. Other grammar stays advisory in **Check these**.

Cleaned up never uses a writer rewrite; protected-word and written-time fallback guards are unnecessary. Other slots keep their writer answers, with `fixedSentenceSplits` capitalising recognised ordinary words only at newly introduced inline sentence boundaries. Cleanup preserves existing boundaries and skips recognised abbreviations, code spans and identifier syntax, already-cased acronyms, and unknown words; it is not a general grammar or code parser, and the existing common-word list is the dictionary-unavailable fallback. Both panel writers and both selection writers share this cleanup, and the prompts request sentence case only for newly split sentences. An unchanged local result is omitted without setting `unchanged`; only a writer answer or retry equal to the original can establish that status. Fallback routing accepts any nonempty set of usable polish cards, while replies still require three. The existing duplicate, avoid-list, number/time and layout guards still decide whether a version can be shown; casing and apostrophe corrections count as changes. The spelling-check switch controls background checks and the **Check these** list, independently of requested polish. If loading the dictionary fails, dictionary spelling and contraction fixes are skipped, while article-context and repetition cleanup still run.

## How Ownvoice writes

Setup asks **How should Ownvoice write?**, and Home's **How Ownvoice writes** row keeps the same choice: **On this phone**, private and free, or **With your ChatGPT**, on the plan already paid for. Picking ChatGPT signs in inside its option: tap the button, approve the displayed code on the page that opens, then **Continue**. While a sign-in code is displayed, **Cancel** stops the attempt and returns to the previous screen. The ChatGPT option also holds **Apps that stay on this phone**, the apps that are always written on this phone. Switching back to **On this phone** is immediate; switching to ChatGPT asks first when already signed in, and signing out moves the choice back to the phone where the phone can write. Sign-in uses byokit's device-code flow and Expo SecureStore for credentials; sign-out requests revocation and clears the legacy app choices, and starting a new sign-in clears them too. When ChatGPT is the chosen writer and the app is not phone-only, the drafts panel uses `@byokit/accounts` `accounts.respond` (version pinned in [`package.json`](package.json)) as its main writer, for streamed drafts and selection rewrites. The lab-only phone agent also routes each streamed Responses turn through that kit method, including its tool calls. Ownvoice sets `originator: ownvoice` and asks for `text.format: json_object` for draft arrays; selection rewrites and row retries stay plain text. The kit reads the SSE stream and rejects incomplete answers. The dormant reply helper in `src/chatgpt/responses.ts` accepts closed JSON strings only after their comma or closing bracket arrives, applies cleanup and duplicate checks, and emits cards in their original slots before the full response finishes. The 1.0.3 panel never invokes it: no generic reply is grounded reliably, so the panel withholds all such cards before routing. Final validation still requires the requested array key and count; a failed initial response resets any provisional cards. Rejected slots are retried under their original reply labels. Polish versions and reply retries await their complete responses. The streaming and incomplete-response regressions are in `src/chatgpt/__tests__/responses.test.ts`. Its configured Expo fetch adapter rechecks consent after the kit resolves credentials; read-log marking is described under **Privacy** below. Phone chosen means drafts never go to ChatGPT, even when signed in. If ChatGPT can't answer, this phone writes instead, but only when the phone can write, otherwise the panel shows a plain no-phone line; offline failures say they are offline. If sending is stopped before a request starts, it says only that this phone wrote the drafts (or that ChatGPT is turned off). Both writers share the same draft acceptance rules.

The lab-only compose-from-request script asks its text writer for a single-field JSON object, `{"note":"finished message"}`. It decodes only a complete envelope with exactly one nonblank string field named `note`, optionally enclosed in a JSON fence; other text stays intact, including literal brackets, stars and backticks. The extracted note is the same text displayed, checked and offered for approval. The shared writing instructions require task facts and requested tone changes to be preserved, plain text with `•` for requested lists, unknown recipient names to be omitted, and signatures only when supplied by the task. Capability explanations belong outside the note and only when an action such as sending is requested; the script's text-only writing call omits them entirely. These are instructions to the writer, not enforced prose guarantees. Local writing-rule and number checks do not establish prose faithfulness; live outputs still need inspection. `EXPO_PUBLIC_PHONE_AGENT=1` remains required for the lab screen, and real lab QA uses an isolated adapter without E2E writer or account flags.

**Privacy:** For an enabled app, ChatGPT drafting sends the text being rewritten or replied to, visible screen context and writing rules to OpenAI. Phone-only drafting does not send that content. The read log stores one native tap fact per bubble tap (app, time, what was read and whether a ChatGPT request reached the server — marked only once the server answers, so a vetoed or offline-before-connect request leaves no Sent mark), not the screen or message text, for up to 30 days. Checking the public remote switch makes a GET to GitHub without app-added identifiers; the request still exposes ordinary connection information such as the device's IP address to the host. The signed switch accepts newer verified choices, retains the last verified choice if fetching fails, and is checked again before sending; before any verified flag, it defaults to on. If saving a verified choice fails, that choice lasts only until the process restarts; after a restart with no network, an older saved choice may apply. The signed switch is published at `switch/chatgpt.json` on the default branch. A switch permitting ChatGPT never overrides the chosen source or the phone-only list. Immediately before starting a ChatGPT request, the app checks its latest source, sign-in, pause, phone-only and switch state; withdrawing consent before this last check keeps drafts on the phone. The selection rewrite sends through the same latest sign-in, pause and switch checks plus its stored writing choice; it rewrites text from any app, so no phone-only choice applies to it.

Live proofs run through the app on the signed-in test emulator, using its byokit sign-in. Never read or copy another tool's credentials for a proof. See the [current release A/B report](reports/accounts-090-live-ab.md) for candidate evidence; the [earlier in-app proof](reports/live-proof-p9.md) records the reverted transport's history.

To produce a switch flag offline, keep a 32-byte private signing key as hex outside this repository and, from `mobile/`, run `SWITCH_SEQ=1 node --experimental-strip-types scripts/sign-switch.ts /path/to/private-key off` (increment the sequence for later flags). This prints the signed JSON; it does not publish it. Never commit the private key.

### Reply fit (Jev)

`src/grow/fit.ts` asks Jev, through the published `@byokit/decide` `jev()`, one
score question per shown text on X and Reddit replies: the platform rubric is the
question and Jev's most probable level (`LEVELS`) becomes the card's engagement
level. Below decide's 0.6 floor the card says it isn't sure; when nothing answered
(no key, no consent, offline, the 20 second deadline) it says it can't rate the fit
and keeps the text checks below. The level is never adjusted by hand rules. The
panel asks once per tap after the cards land, never per keystroke, and never for
an edited text; each call uses a fresh in-memory cache.

A reply typed under an X or Reddit post opens grow mode (`modeOf` in `src/panel/Panel.tsx`):
the writer gets their text as `point` (with `typed` empty) so the replies start from it,
**Yours** keeps their text, and once the fit answers the cards are listed highest level first,
unrated ones last and ties in slot order. Each card keeps its `slot`, so its tag still names
what it is for. With no fit answer the cards stay in slot order. Elsewhere typed text is polished.

`fitBackends(app)` in `src/chatgpt/settings.ts` builds the Jev backend from the
build's `EXPO_PUBLIC_JEV_KEY` (no key: no backend) and sends only under the same
consent as a ChatGPT send for that app (source, visibility, pause, phone-only,
sign-out epoch, remote switch), checked again at dispatch. Drafts the phone wrote
are never sent. Jev is billed per use to that key.

Proof without a key: `node e2e/jev-standin.mjs serve` answers Jev's wire format
from a local model's token probabilities (ollama, `OLLAMA`/`MODEL`), and
`node e2e/jev-standin.mjs rate e2e/jev-cases.json` runs the 10 posts x 3 replies
through `judgeFit` and `jev()`. On an emulator, build with `EXPO_PUBLIC_E2E_GPT=1

### Card ratings

On feed apps (X, Reddit and the other known platforms) each draft card carries two
ratings: an engagement rating, which on X and Reddit replies is Jev's fit level
(above), and otherwise lists only the concerns the text shows on that platform (or
"Nothing flagged") from `packages/engine/src/ratings.ts`; it always says text alone
can't predict reach. Apart from it sits a separate
stock-wording rating from the shared slop rules. A reply whose post couldn't be read
says so instead of comparing. **Edit** opens a card's text; the ratings follow the
edited text (text checks only; Jev isn't asked again), **Insert** puts exactly that text in the box and nothing is posted.

Known limit: the read-screen → rated card → edit → insert flow has not been proven
on the native X app. No demo device with X installed and signed in exists, so the
evidence is unit and panel tests only.

## Signed APK releases

The [APK release workflow](../.github/workflows/apk-release.yml) builds the Expo app on tags such as `v1.0.0`, verifies its signature, and publishes `Ownvoice.apk` plus its SHA-256 alongside the GitHub Release. Before tagging, update `expo.version` and increase `android.versionCode` in `app.config.js`; the tag must match `expo.version`. Tag only reviewed commits on current `main`; the workflow rejects a tag that points elsewhere. Download links use `releases/latest/download/Ownvoice.apk` so they survive version updates. A manual workflow run on the version tag can retry a failed build before the release is published.

The repository's Actions secrets are `OWNVOICE_KEYSTORE_BASE64`, `OWNVOICE_STORE_PASSWORD`, `OWNVOICE_KEY_ALIAS` and `OWNVOICE_KEY_PASSWORD`. The workflow restores the key only in the runner's temporary directory, passes credentials to Gradle as environment variables, and deletes the key even after failure. Never commit keys or passwords. The Expo plugin enables dedicated signing only with `OWNVOICE_RELEASE_SIGNING=1`; missing credentials then fail the build. Ordinary local release builds still use Expo's development key and cannot update the published app. Use a separate emulator or remove the local build first.

For an authorized local signed build, set `OWNVOICE_RELEASE_SIGNING=1`, `OWNVOICE_KEYSTORE_PATH` (an absolute path) and the three credential variables above, then run the regular release build. Distributable APKs must have all `EXPO_PUBLIC_*` proof flags unset. The published APK includes ARM64 for phones and x86_64 for emulator installation proof. Signature verification follows [Android apksigner](https://developer.android.com/tools/apksigner); credential storage follows [GitHub Actions secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).
