**Check my spelling as I type** (Home, off by default, stored as `typingCheck` in the native prefs) is the one time Ownvoice reads without a tap. `OwnvoiceService` listens to `TYPE_VIEW_TEXT_CHANGED` only while it is on, from switched-on apps while not paused; a change only re-arms a 700 ms pause, and nothing is read per keystroke. At the pause it reads the focused, editable, non-password field once, and text of at least 12 characters and three words that differs from the last checked text goes to JavaScript as `onTyped({ app, text })`; if no screen of Ownvoice is open, the service starts the React Native host headless and the pause waits until `src/core/typingCheck.ts` listens. One check runs at a time; a newer pause replaces any waiting one. The check (`src/core/typing.ts`) counts unknown words from Hunspell's English dictionary (`nspell` with dictionary-en 4.0.0's files, kept in `assets/dictionary/` with their license and read on first use, `src/core/speller.ts`), a short hand-written list of slips (its/it's, lets/let's, a/an, doubled words, lowercase i, a missing capital, then/than; lowercase i and a missing capital only when the text uses capitals elsewhere) and the `slop.ts` marks with Your voice's rules. There is no advisory your/you're rule: a short next-word list cannot reliably distinguish possessive noun phrases such as "your right hand" and "your welcome letter". Spelling still offers the missing apostrophe in "youre". The count shows as an amber badge on Dot (`showSlips`, dropped when another app comes to the front or the field falls below the minimum); suggestions are never worked out on a pause. A tap opens the usual panel, which lists each slip under **Check these** with its own **Fix**; Fix inserts the typed text with that one slip fixed through the same insert path as a draft, only when pressed. Nothing is sent, the text is held only until the pause, and no read-log entry is written per pause. The service logs `typing check ms=… badge ms=…` for each answer, which is how the on-phone timing is measured.

## Cleaned up acceptance

The user-facing behavior is described in [Polish what you wrote](../README.md#polish-what-you-wrote). Both phone and ChatGPT polish use `src/core/polish.ts` for initial acceptance and retry. It seeds slot 0 with `fixedSlips` from `src/core/typing.ts` applied only to the original text, ignoring writer answers and retries for that slot. Both writers request only Shorter and Main point first. Automatic contraction fixes reuse the lowercase keys of the null-prototype `APOSTROPHE` map, excluding `AMBIGUOUS_APOSTROPHE`; inherited object keys cannot match. Other automatic spelling covers only unknown lowercase words in the three-entry `AUTO_SPELLING` map; dictionary suggestions remain advisory. Spelling corrections run before doubled-word removal, which uses `DOUBLE_WORDS` (articles only), a lowercase first occurrence, and whole-word boundaries outside handles, tags, URLs and emails. Other repeated words stay unchanged in Cleaned up. After spelling and repetition cleanup, the only automatic grammar rule is `Its`/`its` immediately before a space and the lowercase whole word `a`, `an` or `the`, preserving case. Other grammar stays advisory in **Check these**.

Cleaned up never uses a writer rewrite; protected-word and written-time fallback guards are unnecessary. Other slots keep their writer answers. An unchanged local result is omitted without setting `unchanged`; only a writer answer or retry equal to the original can establish that status. Fallback routing accepts any nonempty set of usable polish cards, while replies still require three. The existing duplicate, avoid-list, number/time and layout guards still decide whether a version can be shown; casing and apostrophe corrections count as changes. The spelling-check switch controls background checks and the **Check these** list, independently of requested polish. If loading the dictionary fails, dictionary spelling and contraction fixes are skipped, while article-context and repetition cleanup still run.

## How Ownvoice writes

Setup asks **How should Ownvoice write?**, and Home's **How Ownvoice writes** row keeps the same choice: **On this phone**, private and free, or **With your ChatGPT**, on the plan already paid for. Picking ChatGPT signs in inside its option: tap the button, approve the displayed code on the page that opens, then **Continue**. While a sign-in code is displayed, **Cancel** stops the attempt and returns to the previous screen. The ChatGPT option also holds **Apps that stay on this phone**, the apps that are always written on this phone. Switching back to **On this phone** is immediate; switching to ChatGPT asks first when already signed in, and signing out moves the choice back to the phone where the phone can write. Sign-in uses byokit's device-code flow and Expo SecureStore for credentials; sign-out requests revocation and clears the legacy app choices, and starting a new sign-in clears them too. When ChatGPT is the chosen writer and the app is not phone-only, the drafts panel uses `@byokit/accounts` `accounts.respond` (version pinned in [`package.json`](package.json)) as its main writer, for streamed drafts and selection rewrites. The lab-only phone agent also routes each streamed Responses turn through that kit method, including its tool calls. Ownvoice sets `originator: ownvoice` and asks for `text.format: json_object` for draft arrays; selection rewrites and row retries stay plain text. The kit reads the SSE stream and rejects incomplete answers. For replies, `src/chatgpt/responses.ts` accepts closed JSON strings only after their comma or closing bracket arrives, applies cleanup and duplicate checks, and emits accepted cards in their original slots before the full response finishes. Final validation still requires the requested array key and count; a failed initial response resets any provisional cards. Rejected slots are retried under their original reply labels. Polish versions and reply retries await their complete responses. The streaming and incomplete-response regressions are in `src/chatgpt/__tests__/responses.test.ts`. Its configured Expo fetch adapter rechecks consent after the kit resolves credentials; read-log marking is described under **Privacy** below. Phone chosen means drafts never go to ChatGPT, even when signed in. If ChatGPT can't answer, this phone writes instead, but only when the phone can write, otherwise the panel shows a plain no-phone line; offline failures say they are offline. If sending is stopped before a request starts, it says only that this phone wrote the drafts (or that ChatGPT is turned off). Both writers share the same draft acceptance rules.

**Privacy:** For an enabled app, ChatGPT drafting sends the text being rewritten or replied to, visible screen context and writing rules to OpenAI. Phone-only drafting does not send that content. The read log stores one native tap fact per bubble tap (app, time, what was read and whether a ChatGPT request reached the server — marked only once the server answers, so a vetoed or offline-before-connect request leaves no Sent mark), not the screen or message text, for up to 30 days. Checking the public remote switch makes a GET to GitHub without app-added identifiers; the request still exposes ordinary connection information such as the device's IP address to the host. The signed switch accepts newer verified choices, retains the last verified choice if fetching fails, and is checked again before sending; before any verified flag, it defaults to on. If saving a verified choice fails, that choice lasts only until the process restarts; after a restart with no network, an older saved choice may apply. The signed switch is published at `switch/chatgpt.json` on the default branch. A switch permitting ChatGPT never overrides the chosen source or the phone-only list. Immediately before starting a ChatGPT request, the app checks its latest source, sign-in, pause, phone-only and switch state; withdrawing consent before this last check keeps drafts on the phone. The selection rewrite sends through the same latest sign-in, pause and switch checks plus its stored writing choice; it rewrites text from any app, so no phone-only choice applies to it.

Live proofs run through the app on the signed-in test emulator, using its byokit sign-in. Never read or copy another tool's credentials for a proof. See the [current release A/B report](reports/accounts-090-live-ab.md) for candidate evidence; the [earlier in-app proof](reports/live-proof-p9.md) records the reverted transport's history.

To produce a switch flag offline, keep a 32-byte private signing key as hex outside this repository and, from `mobile/`, run `SWITCH_SEQ=1 node --experimental-strip-types scripts/sign-switch.ts /path/to/private-key off` (increment the sequence for later flags). This prints the signed JSON; it does not publish it. Never commit the private key.

### Reply fit judge (growth foundation)

`src/grow/fit.ts` judges a draft and its alternatives for X or Reddit in one
`@byokit/decide` call, through a pluggable ordered backend list. The platform
rubrics estimate text fit, not reach or calibrated engagement probabilities.
Never-say phrases, long dashes (regardless of the saved no-dashes rule),
platform limits and links, including bare domains and Markdown destinations,
are checked first; flagged candidates and their questions are omitted from
the outward request. Ordinary sentence dots, decimals and abbreviations such
as "e.g." are not links. Bare domains must end in a registered suffix from
`src/grow/domainEndings.json`, bundled from [IANA’s root list](https://data.iana.org/TLD/tlds-alpha-by-domain.txt)
(2026-10-02), so non-domain endings such as `.json` and `.keys` stay eligible.
Domain labels and suffixes include Unicode combining marks; suffix lookup
uses NFC normalization. Email addresses remain eligible unless explicitly
linked.
The statement-ending preference applies to posts,
so reply questions remain eligible. X replies lose one level for two or more
hashtags, including punctuation-separated tags, and another for a trailing
request for thoughts or agreement. An earlier ask followed by another
sentence does not trigger that drop. The bounded English rule recognizes
`Thoughts?`, `Any thoughts?`, `What do you think?`, `Agree?`, `What about you?`,
`What are your thoughts`, `Share your thoughts`, and `Let me/us know` followed
by `your thoughts` or `what you think`. `Please` is optional. The first five
forms require a question mark; the remaining forms also allow a period,
exclamation mark or no ending. Requests begin at the reply start or a
sentence/clause separator. Optional topics begin with `on`,
`about` or `of` and may contain commas; sentence punctuation, semicolons,
colons and newlines end topics. It does not infer unlisted paraphrases or
quote-bearing replies. Matches with question or reporting prefixes, and comma
clauses beginning with explicit question words, are excluded conservatively.
Blank lines retain preceding question/reporting context; only sentence
punctuation resets that context. Question openings at each retained line or
clause start are excluded. Ambiguous multiline requests may receive no drop.
Unknown platforms use rules only.

`fitBackends(app, events)` in `src/chatgpt/settings.ts` supplies the ChatGPT
answerer through the existing `responses.ts` ask path and accounts response
transport. It rechecks source, app visibility, pause, phone-only routing,
sign-out epoch and a known-on remote switch before sending and at dispatch.
Pass `sent` with the tap's read-log hook, as with the writer. A veto, timeout or
malformed answer yields rules only. The deadline is 20 seconds; each invocation
uses a new in-memory decision cache, so text is never cached across taps.
The confidence floor is decide's 0.6; abstained best picks never affect order.
This foundation does not yet wire the judge into the panel or change posting.

## Signed APK releases

The [APK release workflow](../.github/workflows/apk-release.yml) builds the Expo app on tags such as `v1.0.0`, verifies its signature, and publishes `Ownvoice.apk` plus its SHA-256 alongside the GitHub Release. Before tagging, update `expo.version` and increase `android.versionCode` in `app.config.js`; the tag must match `expo.version`. Tag only reviewed commits on current `main`; the workflow rejects a tag that points elsewhere. Download links use `releases/latest/download/Ownvoice.apk` so they survive version updates. A manual workflow run on the version tag can retry a failed build before the release is published.

The repository's Actions secrets are `OWNVOICE_KEYSTORE_BASE64`, `OWNVOICE_STORE_PASSWORD`, `OWNVOICE_KEY_ALIAS` and `OWNVOICE_KEY_PASSWORD`. The workflow restores the key only in the runner's temporary directory, passes credentials to Gradle as environment variables, and deletes the key even after failure. Never commit keys or passwords. The Expo plugin enables dedicated signing only with `OWNVOICE_RELEASE_SIGNING=1`; missing credentials then fail the build. Ordinary local release builds still use Expo's development key and cannot update the published app. Use a separate emulator or remove the local build first.

For an authorized local signed build, set `OWNVOICE_RELEASE_SIGNING=1`, `OWNVOICE_KEYSTORE_PATH` (an absolute path) and the three credential variables above, then run the regular release build. Distributable APKs must have all `EXPO_PUBLIC_*` proof flags unset. The published APK includes ARM64 for phones and x86_64 for emulator installation proof. Signature verification follows [Android apksigner](https://developer.android.com/tools/apksigner); credential storage follows [GitHub Actions secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).
